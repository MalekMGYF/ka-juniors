# K.A Juniors

موقع تسجيل + ترتيب (Leaderboard) + لعبة "خمن الطالب" بنظام كوينات، مبني بـ Next.js وقاعدة بيانات Supabase (مجانية)، وجاهز للرفع على Vercel (مجاني).

## 1) اعمل قاعدة البيانات (5 دقايق)

1. روح على https://supabase.com واعمل حساب مجاني، وأنشئ مشروع جديد (New Project).
2. من صفحة المشروع، روح على **SQL Editor** والصق فيه محتوى ملف `supabase-schema.sql` الموجود في المشروع ده، ودوس **Run**. الأمر ده هيعمل الجداول المطلوبة (المستخدمين، الأسئلة، الإجابات، التلميحات).
3. روح على **Settings -> API** وهتلاقي:
   - **Project URL** → ده اللي هتحطه في `NEXT_PUBLIC_SUPABASE_URL`
   - **service_role key** (تحت API keys) → ده اللي هتحطه في `SUPABASE_SERVICE_ROLE_KEY`

⚠️ الـ service_role key ده سري جدًا، متحطهوش غير في إعدادات Vercel (Environment Variables)، ومتنشروش في الكود العام.

## 2) الرفع على Vercel

1. اعمل ريبو على GitHub وارفع مجلد المشروع ده فيه.
2. روح على https://vercel.com، اعمل New Project، واختار الريبو ده.
3. في خطوة الإعدادات، ضيف الـ Environment Variables دي:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `SESSION_SECRET` → أي نص عشوائي طويل من عندك
   - `ADMIN_PASSWORD` → الباسورد بتاعك انت للدخول على لوحة التحكم
4. دوس Deploy وخلاص، الموقع هيبقى شغال على رابط `xxxx.vercel.app`.

## 3) إزاي تدخل صفحة الأدمن

روح على:

```
https://your-site.vercel.app/admin/login
```

واكتب نفس الباسورد اللي حطيته في `ADMIN_PASSWORD`. بعد الدخول هتدخل مباشرة على `/admin` وتقدر:

- تضيف سؤال جديد للعبة "خمن الطالب": الوصف اللي هيظهر للطلاب، اسم الطالب الصحيح (الإجابة)، والتلميح.
- توقف/تشغل أي سؤال وقت ما تحب.
- تمسح أي سؤال.

أي سؤال تضيفه بيظهر فورًا لكل الطلاب المسجلين في صفحة `/game` من غير ما تعمل أي حاجة تانية، لأن كل حاجة متخزنة في قاعدة البيانات مش على جهازك.

## 4) إزاي اللعبة شغالة

- كل طالب يشوف السؤال (الوصف) ويكتب اسم اللي يعتقد إنه هو، بدون حدود على عدد المحاولات.
- لو جاوب صح: ياخد نقطة واحدة + 5 كوين، ويختفي السؤال ده من عنده (يفضل يظهر لباقي اللي لسه ما جاوبوش).
- التلميح بـ 10 كوين، وبمجرد ما حد يشتريه بيفضل ظاهرله دايمًا (مش بيتخصم منه تاني).
- الترتيب في `/leaderboard` بيترتب بالنقط، وبيظهر لكل المسجلين في الموقع.

## التشغيل محليًا (لو حابب تجرب على جهازك قبل الرفع)

```bash
npm install
cp .env.example .env.local   # واملى القيم الصح
npm run dev
```

## لعبة «ارسم واتقال»

أضيفت اللعبة داخل المسار المحمي `/pictionary`، وتظهر أيضًا من قائمة الألعاب في الغلاف المشترك. في الجولة يختار الرسّام كلمة من ثلاث اختيارات، يرسم على لوحة canvas، وتصل التخمينات إلى الشات. أول تخمين صحيح يحصل على 35 نقطة و8 كوين، بينما يحصل الرسّام على 15 نقطة و4 كوين في منطق الجولة المحلي.

لتفعيل الغرف الجماعية الفعلية، شغّل ملف `supabase-migration-pictionary.sql` كاملًا في Supabase SQL Editor بعد بقية migrations. الـ route handler الموجود في `app/api/pictionary/route.ts` يستخدم `SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط، ويحدّث الغرفة والرسائل والخطوط والنتيجة من دون كشف المفتاح للمتصفح. عند غياب جداول اللعبة أو بيانات Supabase في بيئة المعاينة، تبقى الواجهة قابلة للتجربة محليًا وتعرض ملاحظة وضع التجربة بدل أن تتعطل.

بعد إضافة migration، جرّب تسجيل الدخول ثم افتح `/pictionary`. ستظهر شاشة Lobby فيها «إنشاء روم» أو «دخول الروم» بكود مثل `KJ-ABCD`. صاحب الروم يرسل الكود لأصحابه، ولا يظهر زر «ابدأ اللعبة» فعالًا إلا بعد دخول 3 لاعبين على الأقل، والروم تقبل حتى 6 لاعبين. الجولة مدتها دقيقتان، ويظهر أول فائز فورًا داخل الجولة، ثم تنتهي تلقائيًا عندما يجيب الجميع أو ينتهي الوقت. زر الخروج أسفل اللعبة يطلب تأكيدًا قبل مغادرة الروم.

إذا كانت جداول اللعبة موجودة من migration قديم، شغّل الملف مرة أخرى حتى تُضاف أعمدة `max_players` و`tool` الجديدة باستخدام `if not exists` بأمان.

## بنك كلمات ارسم واتقال

افتح `/admin` ثم تبويب **كلمات ارسم واتقال** لإضافة الكلمات والبحث عنها وحذفها. بعد تشغيل `supabase-migration-pictionary.sql` ستضاف ثلاث كلمات بداية تلقائيًا، ويمكنك حذفها أو إضافة أي عدد من الكلمات. في بداية كل جولة تسحب اللعبة 3 كلمات عشوائية من الكلمات الموجودة في البنك؛ إذا كان البنك يحتوي أقل من 3 كلمات، سيظهر تنبيه لصاحب الروم لإضافة كلمات من الأدمن قبل البدء.

### تفعيل المزامنة الفورية

أصبحت الغرفة تستخدم **Supabase Realtime Broadcast** بدل polling دوري. أضف `NEXT_PUBLIC_SUPABASE_ANON_KEY` إلى Secrets الخاصة بالبيئة بجانب `NEXT_PUBLIC_SUPABASE_URL`. المفتاح العام يستخدمه المتصفح للاشتراك في قناة الغرفة فقط، بينما يظل `SUPABASE_SERVICE_ROLE_KEY` داخل route handlers على الخادم. بعد إضافة المفتاح، أعد تشغيل التطبيق وتحقق من ظهور عبارة «Realtime شغال — التحديثات بتوصل فورًا» أسفل لوحة الرسم. عند انقطاع القناة يحاول التطبيق إعادة الاشتراك ويحتفظ بالـ snapshot الأخير بدل إيقاف الجولة.
